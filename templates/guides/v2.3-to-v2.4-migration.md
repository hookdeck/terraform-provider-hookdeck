---
page_title: "Migrating from v2.3 to v2.4"
description: "How to migrate from v2.3 to v2.4 of the Hookdeck Terraform Provider"
---

This release adds support for destination delivery policies and delivery groups, with a breaking configuration change that requires updating destinations using delivery rate or group settings.

## Breaking Change

### Changed: Destination Delivery Policy Configuration

Destination operations now use Hookdeck API version `2026-09-01`, matching the [API breaking change](https://hookdeck.com/docs/api#2026-09-01). In v2.4, existing Terraform configurations using the old fields must be edited before upgrading and applying. The provider does not translate legacy configuration or automatically rewrite state; a plan whose destination `config` still contains the old fields fails with an error naming them.

**Action Required**: Replace `rate_limit`, `rate_limit_period`, and `delivery_groups` with the corresponding fields under `delivery_policy` in each affected destination configuration.

#### Affected Configuration

The JSON `config` on `hookdeck_destination` uses the new delivery policy structure for HTTP and Mock API destinations. Destinations without delivery rate or group settings need no configuration changes. Connections continue to reference destinations through `destination_id`; no connection configuration change is required.

| Previous config field | New config field |
| --- | --- |
| `rate_limit` | `delivery_policy.rate` |
| `rate_limit_period` | `delivery_policy.period` |
| `delivery_groups` | `delivery_policy.groups` |
| `delivery_groups.rate_limit` | `delivery_policy.groups.rate` |
| `delivery_groups.rate_limit_period` | `delivery_policy.groups.rate_period` |
| `delivery_groups.overrides.<value>.rate_limit` | `delivery_policy.groups.overrides.<value>.rate` |
| `delivery_groups.overrides.<value>.rate_limit_period` | `delivery_policy.groups.overrides.<value>.rate_period` |

As in previous API migrations, `config` remains a JSON string and its contents are validated by the API on apply. The provider has no translation layer or state upgrader for this change. The new API ignores unknown fields, including the retired field names, so without a check a successful apply would not establish that legacy delivery settings were applied. The provider therefore rejects `rate_limit`, `rate_limit_period`, and `delivery_groups` at plan time. Update the configuration explicitly.

Group and override periods use `rate_period`; the destination-wide period uses `period`.

```hcl
# Before (v2.3)
resource "hookdeck_destination" "api" {
  name = "my-api"
  type = "HTTP"
  config = jsonencode({
    url               = "https://example.com/webhooks"
    rate_limit        = 100
    rate_limit_period = "minute"
    delivery_groups = {
      key               = "body.customer_id"
      rate_limit        = 5
      rate_limit_period = "second"
      overrides = {
        priority = {
          rate_limit        = 10
          rate_limit_period = "second"
        }
      }
    }
  })
}

# After (v2.4)
resource "hookdeck_destination" "api" {
  name = "my-api"
  type = "HTTP"
  config = jsonencode({
    url = "https://example.com/webhooks"
    delivery_policy = {
      rate   = 100
      period = "minute"
      groups = {
        key         = "body.customer_id"
        rate        = 5
        rate_period = "second"
        overrides = {
          priority = {
            rate        = 10
            rate_period = "second"
          }
        }
      }
    }
  })
}
```

## New Features

- **Delivery Policies**: Configure destination-wide delivery rates using `delivery_policy.rate` and `delivery_policy.period`.
- **Delivery Groups**: Configure per-group rates and overrides using `delivery_policy.groups`.

## Improvements

- Removed policy members and overrides are cleared when updating a previously migrated configuration.
- Destination requests use the current API delivery policy structure without prior-version compatibility logic.

## Troubleshooting

### Plan Fails With "Destination config uses removed fields"

After upgrading, `terraform plan` reports this error on every `hookdeck_destination` whose `config` still contains `rate_limit`, `rate_limit_period`, or `delivery_groups`. The error lists the offending fields. To migrate:

1. Update each affected destination's JSON configuration using the mapping above. Preserve all existing rate, period, group, and override settings that should remain active.
2. Update your provider version constraint to v2.4:

   ```hcl
   terraform {
     required_providers {
       hookdeck = {
         source  = "hookdeck/hookdeck"
         version = "~> 2.4.0"
       }
     }
   }
   ```

   Reinitialize Terraform to download the provider:

   ```bash
   terraform init -upgrade
   ```
3. Run `terraform plan` and review the destination configuration updates. Changing the JSON to the new field names should produce an in-place config update.
4. Run `terraform apply`. The configuration update uses the existing destination ID; it does not require replacing the destination, removing state, or reimporting it. Terraform records your new configuration in state after applying it.

### Removing Existing Settings During Migration

To disable all existing rate and group settings during migration, explicitly set `delivery_policy = null`. Simply deleting the old fields does not instruct the new API to clear their stored values. For a partial policy during migration, explicitly set unwanted `rate`, `period`, or `groups` members to `null`.

After migration, removing a previously configured policy member clears it on the API; removing `groups` disables groups, and removing an override replaces the group's overrides. Removing the entire `delivery_policy` also clears it.
