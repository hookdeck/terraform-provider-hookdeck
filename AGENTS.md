# Agent guide

This file is for AI coding agents (Claude Code, Cursor, Copilot, and similar) working on this repository. It complements [`README.md`](README.md) (user-facing) and [`CONTRIBUTING.md`](CONTRIBUTING.md) — read `CONTRIBUTING.md` for development environment setup, the test harness, CI behavior, and the release process. This file collects orientation and norms specific to working in this codebase as an agent.

## Project layout

- [`internal/provider/`](internal/provider/) — resource and data-source implementations built on the [Terraform Plugin Framework](https://developer.hashicorp.com/terraform/plugin/framework). Each resource package (`source/`, `destination/`, `connection/`, `transformation/`, `sourceauth/`, `webhookregistration/`) typically contains `resource.go`, `model.go`, `sdk.go`, and `resource_test.go` (acceptance tests).
- [`internal/sdkclient/`](internal/sdkclient/) — thin wrapper around the [Hookdeck Go SDK](https://github.com/hookdeck/hookdeck-go-sdk).
- [`docs/`](docs/) — **generated** from the provider schema. Do not edit by hand; run `go generate ./...` after schema changes.
- [`examples/`](examples/) — example Terraform configurations referenced by the generated docs.
- [`templates/`](templates/) — `tfplugindocs` templates for the generated `docs/`.
- [`cmd/teardown/`](cmd/teardown/) — utility to wipe orphaned resources from a workspace after interrupted acceptance runs.

## Commands and setup

See [`CONTRIBUTING.md`](CONTRIBUTING.md) for build, test, lint, and codegen commands, as well as `.env.test` setup for acceptance tests. Acceptance tests hit the live Hookdeck API and create/destroy real resources — always use a dedicated test workspace.

## Norms

- **Verify locally before pushing CI fixes.** Reproduce the failing check locally and confirm it is green before pushing — don't iterate via CI cycles.
- **Don't append agent attribution footers to PR or issue comments** (e.g. "Generated by …"). Comments are conversational and posted under the maintainer's identity; an attribution footer undermines them. `Co-Authored-By:` trailers in commit messages are a separate convention and unaffected.
- **The Hookdeck API merges `config` updates by presence.** Top-level keys omitted from an update payload are preserved on the API side, so changes that remove a key must send `null` explicitly. See [`internal/provider/source/sdk.go`](internal/provider/source/sdk.go) and [`internal/provider/destination/sdk.go`](internal/provider/destination/sdk.go) for the pattern.
- **The OpenAPI spec under-declares some validation.** When server behavior contradicts the spec, the server is authoritative. If you have access to the API server source, prefer reading the handler over empirical probing.
- **Schema changes require regenerated docs.** CI fails the `generate` job on any uncommitted diff. Run `go generate ./...` and commit the result.
